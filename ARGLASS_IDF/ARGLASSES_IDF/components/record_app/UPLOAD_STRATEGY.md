# 上传策略说明：保留本地备份

## 📋 策略概述

**核心原则**：**永远不删除SD卡上的录音文件**

上传到服务器后，本地SD卡上的文件仍然保留，作为数据备份。

## 🎯 为什么保留本地备份？

### 1. 数据安全
- ✅ 服务器可能故障或丢失数据
- ✅ 上传过程中可能中断
- ✅ 网络不稳定可能导致上传失败
- ✅ 本地备份确保数据永远不会丢失

### 2. 离线访问
- ✅ 没有网络时仍可访问录音
- ✅ 可以在本地播放或处理
- ✅ 不依赖服务器可用性

### 3. 灵活性
- ✅ 可以选择性删除旧文件
- ✅ 可以手动管理存储空间
- ✅ 可以在本地进行备份或迁移

## 📊 上传流程

### 流程图
```
录音完成
    ↓
触发上传任务
    ↓
检查WiFi状态
    ├─ 未连接 → 暂停（文件保留在SD卡）
    └─ 已连接 → 开始上传
                    ↓
              分块传输（4KB/块）
                    ↓
              每40KB检查网络
                    ├─ 断开 → 快速退出，标记待重试
                    └─ 正常 → 继续传输
                    ↓
              上传成功 → 文件保留在SD卡 ✓
              上传失败 → 文件保留等待重试 ✓
                    ↓
              后台监控任务（每30秒检查）
                    ├─ 有待重试 + 网络可用 → 自动重试
                    └─ 其他 → 等待
```

### 关键点
- ✅ **上传成功**：文件保留在SD卡
- ✅ **上传失败**：文件保留等待重试
- ✅ **网络断开**：文件保留等待网络恢复
- ❌ **永远不会删除文件**

### 2. 存储空间监控
```c
// 检查SD卡剩余空间
void check_storage_space() {
    struct statvfs stat;
    if (statvfs("/sdcard", &stat) == 0) {
        unsigned long free_space = stat.f_bsize * stat.f_bavail;
        ESP_LOGI(TAG, "SD卡剩余空间: %lu KB", free_space / 1024);
        
        if (free_space < 10 * 1024 * 1024) {  // 小于10MB
            ESP_LOGW(TAG, "⚠️ 存储空间不足，请清理旧文件");
        }
    }
}
```

## 📈 优势对比

| 策略 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **保留备份**（当前） | 数据安全、离线可用 | 占用存储空间 | 重要录音、弱网环境 |
| 上传后删除 | 节省存储空间 | 数据丢失风险 | 临时录音、强网环境 |
| 手动删除 | 完全控制 | 需要用户操作 | 灵活管理 |

**推荐**：使用**保留备份**策略，特别是：
- ✅ 弱网环境（网络不稳定）
- ✅ 重要录音（不能丢失）
- ✅ 移动设备（AR眼镜等）

## 💡 最佳实践

### 1. 存储规划
- **8GB SD卡**：约可存储 500-1000 个短录音（每个1-2分钟）
- **32GB SD卡**：约可存储 2000-4000 个短录音
- **建议**：定期清理不需要的录音

### 2. 备份策略
```
重要录音 → 服务器 + SD卡双备份
普通录音 → 服务器备份，SD卡可清理
临时录音 → 可以删除
```

### 3. 网络策略
```
强网环境 → 立即上传，保留备份
弱网环境 → 等待网络恢复，自动重试
离线环境 → 本地保存，稍后上传
```

## 📝 总结

**当前策略**：
- ✅ 上传成功 → 文件保留在SD卡
- ✅ 上传失败 → 文件保留等待重试
- ✅ 网络断开 → 文件保留等待网络恢复
- ❌ **永远不会自动删除文件**

**优势**：
1. 数据安全（双重备份）
2. 离线可用（不依赖网络）
3. 灵活管理（用户控制删除）

**建议**：
- 定期检查存储空间
- 手动清理不需要的录音
- 重要录音保留，临时录音可删除
