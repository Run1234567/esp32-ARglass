# 弱网环境上传优化说明

## 📋 问题分析

### 原始问题
```
I (75942) RECORD_APP: ✅ 录音安全结束！共写入: 125280 字节
I (75943) RECORD_APP: 📤 上传任务启动: /sdcard/record/REC_046.wav
I (76033) RECORD_APP: esp_http_client_open ret = ESP_OK
E (88568) SIG: 信令断开，5秒后尝试重连...
W (91631) HTTP_CLIENT: Connection timed out before data was ready!
E (91631) RECORD_APP: ❌ 上传失败，状态码: -1
```

**核心问题**：
1. 上传过程中WiFi断开
2. 等待超时后才失败（浪费时间）
3. 没有自动重试机制

## ✨ 优化方案

### 1. 智能重试机制

**改进前**：
- 最大重试次数：3次
- 固定退避：5s, 10s, 20s
- 无网络状态感知

**改进后**：
- 最大重试次数：5次（增加）
- 智能退避：3s, 6s, 12s, 24s, 48s（上限60s）
- 网络状态实时检查
- 待重试标记机制

### 2. 网络状态感知

**新增功能**：
```c
// WiFi事件监听
wifi_event_handler() - 监听WiFi连接/断开事件
upload_retry_monitor_task() - 后台监控任务

// 自动触发
WiFi连接 → 延迟5秒 → 自动重试待上传文件
```

### 3. 传输优化

**改进前**：
- 连接超时：30秒
- 分块大小：2KB
- 无进度日志

**改进后**：
- 连接超时：15秒（快速失败）
- 分块大小：4KB（提高效率）
- 每10个分块输出进度日志
- 实时网络检查（每40KB检查一次）

### 4. 错误处理增强

**新增逻辑**：
```c
// 传输中断时
if (网络断开) {
    记录已传输字节数
    标记待重试
    快速退出（不等待超时）
}

// 重试时
if (WiFi未连接) {
    设置待重试标记
    返回失败（等待网络恢复）
}
```

## 🔧 使用方法

### 1. 初始化监控（在app_main中调用）

```c
#include "record_app.h"

void app_main(void) {
    // ... 其他初始化 ...

    // WiFi初始化后，启动上传监控
    record_app_init_upload_monitor();

    // ... 其他代码 ...
}
```

### 2. 自动工作流程

```
录音完成
    ↓
触发上传任务
    ↓
检查WiFi状态
    ├─ 未连接 → 暂停（文件保留在SD卡）
    └─ 已连接 → 开始上传
                    ↓
              分块传输（4KB/块）
                    ↓
              每40KB检查网络
                    ├─ 断开 → 标记待重试，快速退出
                    └─ 正常 → 继续传输
                    ↓
              上传成功 → 删除本地文件
              上传失败 → 保留在SD卡
                    ↓
              网络恢复后自动重试
```

## 🎯 适用场景

1. **弱网环境**：信号不稳定，频繁断连
2. **移动设备**：AR眼镜、可穿戴设备
3. **长距离传输**：大文件（>100KB）
4. **批量上传**：多个录音文件连续上传

## 💡 最佳实践

### 1. 网络环境差时
- 文件会自动保留在SD卡
- WiFi恢复后自动上传
- 无需手动干预

### 2. 需要手动重试时
```c
// 在WiFi重连事件后调用
retry_failed_uploads(3);  // 最多重试3个文件
```

### 3. 查看上传状态
观察日志标签 `RECORD_APP`：
- ✅ 成功：`🎉 上传成功！`
- ❌ 失败：`❌ 上传失败，状态码: xxx`
- 📊 进度：`📊 传输进度: xxx/xxx bytes (xx.x%)`
- 🔄 重试：`🔄 第 x/5 次重试，等待 x 秒...`

## 📝 注意事项

1. **内存使用**：
   - 上传任务栈：8KB（PSRAM）
   - 监控任务栈：4KB（PSRAM）
   - 发送缓冲区：4KB（增大）

2. **超时设置**：
   - 连接超时：15秒（避免长时间阻塞）
   - 总超时：90秒（适应大文件）
   - 重试延迟：3-60秒（指数退避）

3. **文件保留**：
   - 上传失败的文件不会删除
   - 网络恢复后自动重试
   - 可手动调用 `retry_failed_uploads()` 触发

4. **性能影响**：
   - 监控任务优先级最低（2）
   - 上传任务优先级低（3）
   - 不影响主要功能（录音、拍照）

## 🚀 后续优化建议

1. **断点续传**：
   - 记录已传输字节数
   - 下次从断点继续
   - 需要服务器支持

2. **压缩传输**：
   - 上传前压缩WAV文件
   - 减少传输数据量
   - 适用于大文件

3. **多服务器支持**：
   - 主服务器失败时切换备用
   - 提高可用性

4. **传输加密**：
   - HTTPS支持
   - 数据安全
